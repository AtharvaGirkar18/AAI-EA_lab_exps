This runs the full validation and routing pass through MCP, refreshes rejected_records.csv with reasons, and appends one workflow audit row per candidate to audit_log.csv. The dataset uses generated names and reserved example.test addresses.

Human review simulation

Apply a reviewer action to a synthetic candidate. The action is timestamped in audit_log.csv. Dispatch is unavailable; notification status remains NOT_SENT.

Workflow path

1

Ingest

Read CSV fields and confirm the expected schema.
2

Normalize and validate

Trim whitespace, check required fields, email shape, numeric ranges, and duplicate IDs. Invalid rows do not receive scores.
3

Score transparently

Skills × 0.40 + relevant experience × 0.30 + technical assessment × 0.30. Each contribution is returned with rule version 1.0.
4

Route to a review queue

75–100 shortlist review; 50–74.99 manual review; below 50 not-shortlisted review. All are proposed states pending human review.
5

Draft, review, audit

Draft status-specific messages. An authorized reviewer can approve, edit, hold, or request information. The demo records the review; it never dispatches messages.

MCP server tools

The browser workbench is an MCP client. Each operation discovers and calls tools on a local FastMCP subprocess over stdio.

  • get_dataset_summary
  • process_candidate_batch
  • run_batch_checks
  • evaluate_candidate
  • review_candidate
Qwen 2.5 7B runs locally via Ollama and helps interpret requests and explain observations. It cannot modify scoring rules or decide outcomes.

Classroom limitations

All data and thresholds are synthetic. Performance metrics describe software behavior only; they do not validate hiring criteria or establish fairness. Reviewers must check the criteria and process separately.
