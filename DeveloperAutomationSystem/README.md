# Developer Automation Lab · Experiment 06

A local developer automation project demonstrating MCP with a real Python **FastMCP server**, **ClientSession**, and **stdio transport**. The browser workbench uses your local Ollama `qwen2.5:7b` model for natural-language planning. Tool execution and the benchmark suites remain deterministic, so reported test results do not depend on LLM output.

## Run

Requires Python 3.10+, Ollama, and the Qwen model. From this directory:

```powershell
ollama pull qwen2.5:7b-instruct
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python server.py
```

Open http://127.0.0.1:8000. The default Ollama model tag matches the ProductRecommendation project (`qwen2.5:7b-instruct`). Configure `OLLAMA_URL` and `OLLAMA_MODEL` before starting if your local endpoint or model tag differs. The MCP server is launched as a subprocess over stdio by the client; do not start it separately for the web app.

## Workbench pages

- **Guided workflow** — enter a developer request, then watch each numbered phase advance through Qwen planning, supervisor review, policy checks, live MCP tool discovery, execution, validation, trace persistence, and report creation. Select sequential or parallel execution.
- **Batch tests** — browse the 31-query prompt bank, filter by category, run a selected query or visible suite, and execute the Variation 9 five-run sequential-versus-parallel benchmark. Every query and observed result is displayed for later documentation.
- **MCP tools** — inspect the live `tools/list` response and try the five registered tools.
- **Execution traces** — inspect persisted JSONL records and generated report files.

## Project corpus

`sample_developer_project/` is a synthetic, self-contained Python repository with 24 domain-specific metrics modules (72 searchable functions), a calculator demo, documentation, and a pytest suite covering normal, boundary, and error behavior. It is the local corpus that MCP tools inspect. The modules can be regenerated with `python scripts/generate_sample_corpus.py`. This experiment needs a representative developer code corpus, not a model-training dataset. The batch query bank has 31 varied, reusable test prompts.

## Safety and study notes

Paths are resolved under the sample project only. `run_tests` uses the current Python executable, a subprocess timeout, and a fixed project test directory. A supervisor allowlist and tool argument validation run before calls. Unexpected MCP communication failures receive one retry; invalid inputs and tool-reported errors do not. Traces are appended to `artifacts/mcp_traces.jsonl`; workflow summaries are saved as JSON. The performance suite repeats four independent tool calls five times sequentially and in parallel. Timing values are generated by your machine when you run the lab and should be copied into the experiment report as observed values, not treated as fixed expected results.

## Architecture

```text
Browser UI → local HTTP workbench → Qwen planner (Ollama)
                                  → supervisor → safety policy
                                  → MCP ClientSession / stdio
                                      ↕ JSON-RPC
                                    FastMCP server → sample project
                                  → validator → JSONL trace / report
```
